# Model-fitting code

This folder holds the code that prepared the analysis tables and fitted the Bayesian models reported in the paper. It is copied unchanged from the study's analysis repository at commit `40c425c`, so the script hashes recorded in the run manifests still match. The figures and tables in `../repro/` are built from the posterior summaries this code wrote, which are deposited in the Zenodo record under `08_analysis_ready/results_tables/`.

Run everything from this folder, with the environment in `requirements-fit.txt`:

```bash
cd analysis
pip install -r requirements-fit.txt
python -m scripts.publication_analysis --help
```

Fits used 4 chains with 1,000 warm-up and 1,000 retained draws, target acceptance 0.95 and seed 20260715 (`analysis.yaml`). The full RQ1 stage, which includes M0, M1, the doubled-prior refit, forward-validation folds and deletion refits, took about 16 hours on 4 cores.

## Refitting from the public record

Zenodo record version 1.1.0 or later holds the inputs every reported model reads. `public_inputs.py` copies the record into the directory layout the code expects (`public_inputs/`) and writes one configuration per analysis stage (`analysis.public-rq1.yaml`, `analysis.public-rq2.yaml`, `analysis.public-rq3.yaml`). These differ from `analysis.yaml` only in the input paths, the output folder (`public_runs/`) and the analysis stage; the RQ1 configuration leaves out the thread topics because the reported RQ1 M1 has no topic term. It also writes `public_inputs/source_manifest.json`, the community-to-database record that the data-integrity checks compare with the code (database folders from `06_experiment_config/g*/server_config.json`, experiment ids from `05_browser_telemetry/sessions.csv`); with it, all eleven RQ1 integrity checks pass. The code in `scripts/` is unchanged.

```bash
python -m repro.download --fit --dest data      # from the repository root: archives 05 to 08 of the newest version
cd analysis
pip install -r requirements-fit.txt
python public_inputs.py --zenodo ../data
```

The commands below use the reported sampler settings (4 chains, 1,000 warm-up and 1,000 retained draws, seed 20260715). For a quick check, the Bayesian commands accept shorter runs (`--draws 150 --tune 150 --chains 2`; `public_criticism.py` takes `--draws` and `--tune`; `rq3_interaction.py` reads `sampling` from the file given with `--config`); short runs fail the sampler gates by design and exit with a non-zero status after writing their tables. Sampling these models is limited by memory bandwidth: on an 8-core desktop processor with two memory channels, one logp-and-gradient evaluation of M1 took 4.5 ms in a single process, 19.5 ms each with four processes and about 41 ms each with eight, so running fits side by side gives little extra throughput there.

Checks against the reported results, October 2026 (staged record 1.1.0, Linux x86-64): the RQ3 estimate tables and all outputs of the sample-size simulation were byte-identical to the reported ones, the direct thread-entry panel had the reported hash, and `validate-rq3` passed all nine gates. Refits at the reported settings agreed with the reported estimates within Monte Carlo error: RQ1 hidden-minus-visible contrast from the main M1 fit +3.48 percentage points (95% CrI +0.63 to +6.30; reported +3.49, +0.51 to +6.50; the rest of the RQ1 stage was not rerun to completion), criticism interaction +13.39 (+5.30 to +21.17; reported +13.28), exploratory downvote interaction +2.35 (+0.34 to +4.42; reported +2.31), and direct thread entry +4.41 (+0.69 to +8.15; reported +4.41, +0.81 to +8.10). A short RQ2 run (2 chains, 300 draws) gave all six prior-contact estimands within 0.11 points of the reported medians. Posterior draws are not bit-identical across machines, so a sampler gate near its threshold can fail on a rerun (the exploratory downvote model's primary fit reached R-hat 1.012 against the 1.01 gate).

## Inputs (original route)

`analysis.yaml` points to the study's processed tables, which are not public in that form. The de-identified versions are in the Zenodo record under `08_analysis_ready/canonical/` (`snapshot_contents.csv`, `snapshot_events.csv`, `snapshot_user_reputation.csv`). Running the preparation code on those tables reproduces the published RQ1 choice sets row for row (2,143 replies, 17,489 candidates, identical attrition), the RQ2 history-support table, and the RQ3 reply panel (2,547 rows, identical cell counts and round timestamps).

Record version 1.0.0 lacks some of these inputs. Version 1.1.0 adds the missing files, and `public_inputs.py` handles the rest:

- **Thread topics for RQ2.** The RQ2 model includes a topic-varying slope for AI authorship (45 topic levels), read from a legacy panel. Without it, every thread is untagged and the topic effect drops out. The reported RQ1 M1 fit has no topic term, so the record's tables reproduce its input exactly (same 17,489 candidate rows and covariates). Version 1.1.0: `08_analysis_ready/model_inputs/thread_topics.csv`, written by `public_inputs.py` under the legacy panel name.
- **Criticism labels for RQ3.** The criticism model uses thread-context labels from a later labelling run. Version 1.0.0 contains the earlier labelling (`07_annotations/llm_annotations/interlocutor_measures.csv`) and the human validation sample only. Version 1.1.0: `07_annotations/llm_annotations/criticism_labels.csv`, read by `public_criticism.py`.
- **Downvote panel for the exploratory interaction model.** The model reads a reply-event panel written by `estimate-rq3`. Version 1.1.0 deposits it as `08_analysis_ready/model_inputs/rq3_vote_panel.csv`; `estimate-rq3` on the public tables also rebuilds it.
- **Browser telemetry for direct thread entry.** The record's `05_browser_telemetry/` files use different names and columns from the private session tables the code reads. `public_inputs.py` converts them. Version 1.1.0 also adds 57 participant sessions that start outside the valid-day windows but have events on the analysis dates; 27 of them are in the direct thread-entry panel.
- **Inputs of the sample-size simulation.** The simulation reads the frame and posterior of the 15 July 2026 M1 fit. Version 1.1.0 deposits the frame and the four variance scales (`08_analysis_ready/model_inputs/reply_observed_design_frame.csv`, `reply_observed_design_scales.json`); `public_inputs.py` writes them back as the files the script reads, with a one-draw posterior that carries the scales.

The run-orchestration code also checks file hashes and paths of the original runs (`runs/...`). Those checks fail outside the original repository and need to be pointed at new run directories. `sol_criticism.py` and `annotation_panels.py` are such cases; `public_criticism.py` replaces them for the public route.
